# Corum Integration

Geode 기반 Geometry Dash 모드다. `LevelInfoLayer`에서 Corum 맵 정보를 조회해 기본 난이도 왼쪽에 Geometry Dash 폰트와 단일 레벨 색을 사용한 난이도 카드, 기본 난이도 위에 현재 순위와 해당 맵을 100%로 완료했을 때의 최대 점수를 표시하고, 왼쪽 위 종이비행기 버튼에서 수동 기록 등록 창을 연다. 난이도 카드의 글자는 배경색의 RGB 밝기를 계산하여 밝은 배경에서는 검정색, 어두운 배경에서는 흰색으로 자동 표시한다.

게임을 실행하면 웹사이트의 `corum-endpoint.json`에서 현재 Apps Script 주소를
받고 Corum 전체 맵 목록을 한 번 내려받는다. 준비가 끝나면
`C Integration is ready` 알림을 표시한다. 실패하면 원인을 포함한 영어 오류
알림을 표시한다.

시작 동기화가 끝난 뒤에는 같은 게임 세션 동안 레벨 화면에서 데이터를 다시
받지 않는다. 따라서 맵 선택 중 네트워크 요청으로 인한 지연이나 성능 저하가
없다. Corum에 등록되지 않은 맵이나 시작 동기화에 실패한 경우에는 정보와
등록 버튼을 포함한 모든 Corum UI가 표시되지 않는다.

맵 관리 시트의 `대체 맵 코드`에 유효한 다른 레벨 ID가 있으면 대표 맵과 대체
맵 양쪽에서 같은 Corum 정보와 등록 버튼이 동작한다. 대표 코드와 대체 코드가
같거나 값이 비어 있으면 대체 맵이 없는 것으로 처리한다. 단일 제출창과 메인 메뉴
일괄 제출창 모두 대표·대체 맵의 저장 기록을 비교하고 더 높은 쪽을 사용한다.

메인 메뉴에서 커스텀 맵 화면으로 진입하면 C Integration 활성화 경고창이 먼저 표시된다. `Continue`를 누르면 진입하고 `Cancel`을 누르면 메인 메뉴에 남는다. 이 경고는 메인 메뉴에서 진입할 때만 표시되며, 하위 화면에서 커스텀 맵 허브로 돌아올 때는 반복되지 않는다.

## 설정

Google Apps Script `/exec` 주소는 웹사이트의
GitHub 저장소 `public/corum-endpoint.json` 원본에서 자동으로 받으므로 게임에서
URL을 직접 입력하지 않는다. 주소가 바뀌면 웹사이트의
`public/corum-endpoint.json`만 수정하고 저장소에 반영한다.
모드를 다시 빌드할 필요는 없다.
Geometry Dash의 Geode 모드 설정에서는 다음 기능만 선택한다.

- `Show Corum difficulty`: Corum 맵에서 색상 난이도 카드, 현재 순위와 100% 최대 점수 표시
- `Record submission`: Corum 맵에서 종이비행기 버튼과 기록 등록 창 표시
- `Record notifications`: 기록 등록·갱신 결과 알림 표시

개인 토큰은 사용하지 않는다. 첫 기록 제출 시 현재 로그인된 Geometry Dash 계정 ID와 닉네임이 서버에 자동 등록된다.

## 기록 등록

- 맵 관리 시트의 최소 등록 가능 기록 이상인 저장 최고 기록만 등록할 수 있다.
- Corum 맵이면 최소 기록 미달이어도 맵 정보 화면 왼쪽 위에 종이비행기 버튼이 나타난다.
- 종이비행기 버튼을 누르면 먼저 로딩 화면이 나타나며 해당 맵의 최신 순위,
  최소 기록, 서버 기록, 현재 획득 점수와 100% 최대 점수를 한 번 다시 받는다.
  로딩이 끝난 뒤에만 제출 양식이 나타난다.
- 최초 제출 전에는 `Estimated Points`에서 현재 최고 기록의 예상 점수와 100% 기록의 최대 점수를 함께 확인할 수 있다. 이 값은 사이트의 `corum-v1` 점수 계산식과 동일하다.
- 해당 맵에 이미 기록이 있고 게임의 최고 기록이 서버 기록보다 높지 않으면 `Locked Points`에 현재 확정 점수가 표시된다.
- 게임의 최고 기록이 서버 기록보다 높으면 `Updated Points`에서 새 기록 제출 시 적용될 점수를 미리 표시한다.
- 맵 순위나 최소 기록만 바뀌어도 점수는 변하지 않는다. 더 높은 퍼센트를 제출한 순간에만 그때의 순위·최소 기록·새 퍼센트로 점수가 다시 확정된다.
- 최소 기록 미달일 때는 현재 기록이 빨간색으로 표시되고 `Submit` 버튼이 비활성화된다.
- 조건을 충족한 뒤 팝업의 `Submit` 버튼을 눌러야만 전송되며 플레이 중 또는 클리어 시 자동 전송하지 않는다.
- 100% 클리어의 로컬 pending 증거가 있으면 `Submit`을 누른 뒤 그 PNG를 먼저
  업로드해 증거 ID를 받은 다음 기록을 전송한다. 플레이 중에는 네트워크 업로드가 없다.
- 전송 중에는 이 준비 과정과 기록 전송 전체를 하나의 흐름으로 처리하며 팝업이
  닫히지 않고 로딩 표시와 `Submitting...` 문구가 나타난다.
- 성공하면 같은 팝업에 Geometry Dash 기본 완료 아이콘과 결과가, 실패하면 기본 삭제 아이콘과 영어 오류 내용이 표시된다.
- 서버 기록보다 높은 최고 기록을 달성하면 같은 버튼으로 다시 보내 기존 기록과 점수를 갱신할 수 있다.
- 플레이어명은 전송 시 게임에 로그인된 현재 Geometry Dash 닉네임을 사용한다.
- 첫 제출에서는 플레이어 자동 등록과 최고 기록 저장이 한 번에 처리된다.
- 같은 기록이나 더 낮은 기록을 다시 보내면 서버 행은 갱신하지 않는다.
- 대표 맵과 대체 맵 중 어느 쪽에서 제출해도 서버에는 대표 맵 코드 하나로
  저장되며, 같은 플레이어의 기록과 점수는 중복 집계되지 않는다.

## 메인 메뉴 일괄 등록

- 메인 메뉴 하단의 종이비행기 버튼을 누르면 최신 Corum 전체 맵 목록과 현재
  Geometry Dash 계정의 서버 기록/점수 데이터를 각각 한 번 새로 받는다.
- 게임에 저장된 온라인 레벨 중 현재 최소 등록 기록을 충족하면서 서버 최고
  기록보다 높은 맵만 후보에 포함한다.
- 서버에 이미 같은 100%가 있어도 이 버전에서 새로 준비된 로컬 완료 캡처가 있으면
  점수를 다시 계산하지 않는 동기화 후보로 한 번 포함해 해당 기록에 연결한다.
- 대표 맵과 대체 맵이 모두 저장되어 있으면 둘 중 높은 일반 모드 기록 하나만
  후보에 포함한다. 퍼센트가 같으면 대표 맵 기록을 사용한다.
- 확인창에서 맵별 현재 퍼센트, 예상 확정 점수, 100% 최대 점수와 모든 제출이
  성공했을 때의 예상 플레이어 총점을 확인할 수 있다.
- 확인창의 `Submit All`을 누르기 전에는 어떠한 기록도 전송하지 않는다.
- `Submit All`을 누르면 pending 100% 증거가 있는 후보의 증거 ID를 먼저 준비한 뒤
  후보 전체 기록을 `batchRecords` JSON 하나로 전송한다. 서버의 기록 등록은 하나의
  잠금과 시트 일괄 쓰기로 전체 후보를 처리한다.
- 처리 중에는 회전하는 로딩 아이콘과 전체 전송 개수가 표시되며, 서버의
  응답 하나가 도착할 때까지 창을 닫을 수 없다.
- 전송이 끝나면 각 맵마다 Geometry Dash 체크 또는 X 아이콘과 결과 메시지가
  표시된다. 일부 맵이 실패해도 나머지 후보의 전송은 계속 진행한다.

## 바로 설치

Windows용 검증 빌드는 프로젝트 루트의 다음 파일에 있다.

```txt
release/hwanhee1.corum_integration.geode
```

이 파일을 Geometry Dash의 `geode/mods` 폴더에 넣고 게임을 다시 시작한다. 필수 의존성은 `Node IDs`뿐이다. v0.2.29부터 CheatAPI는 의존성과 실행 코드에서 모두 제거됐다.

## 빌드

Geode CLI와 SDK를 설치한 뒤 이 폴더에서 실행한다.

```bash
geode build
```

특정 플랫폼을 대상으로 빌드하려면 Geode CLI의 `--platform` 옵션을 사용한다.

```bash
geode build --platform win
geode build --platform android32
geode build --platform android64
```

Android 빌드에는 Geode 공식 문서에 따라 Android NDK와 `ANDROID_NDK_ROOT` 설정이
필요하다. 저장소 루트의 `.github/workflows/build-mod.yml`은 Windows, Android32,
Android64를 각각 빌드한 뒤 하나의 `.geode`로 합치도록 구성되어 있다.

End Screen 증거는 Android의 `MediaProjection`으로 디스플레이를 캡처하지 않는다.
Geometry Dash가 이미 그리는 Cocos scene을 `CCRenderTexture`에 다시 렌더링해서
PNG로 만들고 Geode의 모드 전용 save directory에 저장한다. 따라서 이 기능 자체를
위해 Android의 화면 녹화/화면 공유 런타임 권한 팝업을 요청하지 않는다. 다른 앱이나
Android 시스템 UI를 캡처하는 기능은 아니다.

기존 동봉 바이너리는 Geometry Dash `2.2081`, Geode `5.8.2`를 기준으로 Windows에서
검증된 v0.2.33 빌드였다. v0.2.37의 Android 바이너리는 Android NDK가 준비된 환경 또는
동봉된 CI workflow에서 별도로 빌드·실기기 검증해야 한다.

## 기록 신뢰도

모드는 게임에 저장된 일반 모드 최고 기록과 현재 로그인 계정 정보를 전송한다. 다만 사용자 컴퓨터에서 실행되는 클라이언트이므로 악의적인 변조를 원천 차단할 수는 없다. 서버는 수동 등록 기록을 `unverified`로 저장하며, 검증이 필요한 기록은 운영자가 별도 증거를 확인해야 한다.

v0.2.31부터 Corum Integration 초기화 시점에 실제로 로드된 비내장 Geode 모드의
ID와 버전을 한 번만 수집한다. Corum Integration 자체는 목록에서 제외하며,
`mod.id@version` 형식의 캐시된 목록을 기록 메타데이터로 사용한다. v0.2.33부터는
End Screen PNG가 만들어지는 순간 이 목록과 캡처 시각·플랫폼·게임/모드/Geode 버전을
pending 캡처에 함께 고정하므로, 다음 게임 실행에서 제출하더라도 클리어 당시 정보가
바뀌지 않는다. 이 목록은 기록 판정이나 제출 차단에는 사용하지 않는다.

### 자동 End Screen 증거

- v0.2.29부터 CheatAPI와 기존 클라이언트 치트 판정 코드는 사용하지 않는다.
- Corum에 등록된 맵을 Normal Mode, 비 Test Mode에서 100% 완료해 실제 End Level
  화면이 열린 경우에만 그 화면을 자동 캡처한다.
- 캡처 RenderTexture에는 Cocos 논리 화면 크기를 전달하고 Cocos가 내부에서
  `contentScaleFactor`를 한 번 적용하게 한다. 따라서 실제 렌더 타깃 픽셀 해상도는
  그대로 유지하면서 이중 스케일로 생기던 검은 여백을 제거한다. 리사이즈·다운샘플링
  없이 무손실 PNG로 Geode의 모드 전용 save directory 아래에만 우선 저장한다.
- GPU 픽셀 readback은 렌더 스레드에서 수행하지만 PNG 압축과 디스크 쓰기는 별도
  작업으로 넘겨 End Screen 프레임의 불필요한 정지를 줄인다.
- End Level 창의 등장 애니메이션이 끝나도록 `showLayer` 뒤 0.80초를 기다린 다음
  캡처한다.
- PNG 압축을 시작하기 전에 캡처 메타데이터를 staged 상태로 먼저 저장한다. PNG가
  완전히 기록되면 active pending 증거로 승격하며, 그 사이 게임이 종료된 경우에는
  다음 실행의 Submit/Submit All에서 완성된 staged PNG를 자동 복구한다.
- v0.2.35에서 PNG 저장 직후 종료되어 메타데이터만 유실된 경우에도 같은 계정·대표
  맵 키의 완성된 로컬 PNG를 찾아 복구한다. 실제 PNG 기록 자체가 중간에 끊긴 경우에는
  증거 없는 제출로 넘어가지 않고 다시 클리어해야 한다고 표시한다.
- 클리어 순간에는 서버 요청을 하지 않는다. 같은 계정·같은 대표 Corum 맵을
  제출 전에 여러 번 클리어하면 가장 최근에 정상 저장된 pending PNG 하나만 유지한다.
- 서로 다른 대표 Corum 맵은 각각 독립 PNG와 메타데이터를 유지한다. 앞 맵의 증거를
  업로드하는 중에 다음 맵을 클리어해도 다음 End Screen 캡처를 건너뛰지 않는다.
- 대표 맵과 대체 맵은 동일한 대표 Corum 맵 키를 공유하므로 어느 쪽을 클리어해도
  중복 증거로 취급하지 않는다.
- 서버는 PNG 자체에서 원본 폭·높이를 다시 읽어 `ClearEvidence`에 기록하고,
  Drive의 비공개 `Corum Clear Evidence` 폴더에 원본 파일을 보관한다.
- 로컬 PNG는 종이비행기 `Submit` 또는 메인 메뉴 `Submit All`을 누른 시점에만
  업로드한다. 증거 업로드가 끝나면 반환된 ID를 같은 기록 요청에 붙인다.
- 증거 업로드 뒤 기록 요청이 실패하면 PNG와 반환된 ID를 로컬에 남겨 재시도 시
  이미 올라간 이미지를 중복 업로드하지 않는다.
- 증거와 기록 연결까지 성공하면 로컬 PNG를 삭제하고 계정+대표 맵 완료 표시를
  저장한다. 완료 표시는 서버 `ClearEvidence` 탭의 현재 세대에만 유효하므로 같은
  서버 상태에서는 재클리어해도 새 캡처를 만들지 않지만, 관리 탭을 삭제 후 재설정해
  새 `ClearEvidence` 탭이 생성되면 자동으로 다시 캡처할 수 있다.
- v0.2.32 이전부터 존재한 기록처럼 로컬 pending PNG가 없는 기록도 그대로 수동
  제출할 수 있으며, 이후 다시 100% 클리어하면 새 pending PNG를 만들 수 있다.
- Practice Mode, Test Mode, Corum 외 맵에서는 자동 캡처하지 않는다.
